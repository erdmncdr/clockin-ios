## Layout exception: findings and fix

I read `/tmp/clockin-28-layout-crash.ips`, including both `asiBacktraces`. The important sequence is `StoredLocationBase.beginUpdate` → `GraphHost.flushTransactions` → `NSHostingView.layout` → `NSHostingView.setNeedsUpdate` → `-[NSWindow(NSDisplayCycle) _postWindowNeedsUpdateConstraints]`. This establishes that a SwiftUI stored-state transaction invalidated constraints during the display-cycle layout pass. It does **not** retain the application callback that originally wrote that state.

The concrete feedback path introduced in 27 is in `EarningsChartView`: `onContinuousHover` writes `hoveredDate` synchronously, and `hoveredDate ?? selectedDate` drives the **inline** inspection block. Entering/leaving a bar replaces a one-line instruction with a multi-line detail (including the optional second currency), changing the enclosing List row's height. Relayout updates the tracking geometry under a stationary pointer, which can change hover again. The callback also writes repeated dates/nil without an equality guard. `MacChartReadout`, control hover, and session-row hover had similar unguarded synchronous writes. Those are unsafe layout/interaction boundaries even when the first launch happens to settle.

The fix removes that dependency: hover now draws a non-hit-testing overlay over the chart, while only a deliberate click changes the inline detail. Hover cannot change the chart, row, or tracking region's size. All hover/visibility deliveries use a Mac-only `MacDeferredValue`: one main-queue delivery for the latest value, equality checked against the live binding at delivery time, with stale work discarded when the owner goes away. No binding is read or written synchronously by `submit`. The explicit queue turn is intentional; main-actor isolation alone would not defer a callback already running on the main actor.

**Attribution limit:** this is a source-confirmed feedback mechanism consistent with the report, not a reproduced proof that the captured crash originated at that particular hover callback. There is no application writer frame in the report, and the signed capture loop is unavailable here. The changes remove the identified path and harden the other audited boundaries; your repeated launch/capture run remains the runtime acceptance test. No claim that headless tests reproduce or rule out every AppKit layout exception is made.

## Visual corrections

1. **Today and menu panel:** native `.large` primary/secondary/danger styles now put the full-width, minimum-28-pt content frame **inside** the native button label. Pause/Resume and Clock out expand side by side; Clock out uses the destructive role and red prominent style. Idle Clock in is the single accent-prominent action. The menu panel uses the same danger style rather than the previous accent primary style. The iOS button-style branch is unchanged.
2. **Tab bar:** the bar uses `.glassEffect(.clear.interactive(), in: .capsule)` on macOS 26+, with a light hairline edge and soft shadow. A separate neutral, lightly highlighted clear-glass selection lens carries accent-colored text/icon; it has no accent-filled background. The bar and lens are separate surfaces, without a container merging the nested selection into the outer capsule. Older macOS retains ultra-thin material. Actual refraction/blur and accessibility Reduce Transparency behavior need the signed capture.
3. **Settings:** retains `List(selection:)` / `.sidebar`, removes the extra vertical row padding, restores automatic sidebar background handling, and uses `NSColor.controlAccentColor` for the native system selection instead of the inherited Carbon palette green. Each right pane starts with its localized category title; form controls retain the app palette. Back/Done and existing bindings/sheets remain.
4. **Desk mode:** the timer panel is centered horizontally in the upper wall area (top at 6% of its inset viewport), with a bounded 600 × 260 pt design size that scales down to fit 28% of the available height. The existing material, timer, money, overnight label, corner controls and room crop are retained. At 1440 × 900, the panel occupies approximately y=68…311, above the default desk's y=356 top. The room's default desk starts at source y=104 in all three room assets; the head/desk region below that stays unobscured at 16:10, 16:9 and 3:2. Custom furniture dragged into the upper wall can still intersect the panel; saved room arrangements are not moved.
5. **History:** the summary/chart and ordinary session rows now have transparent row backgrounds over the same page background. The Mac list uses `.plain`, explicit zero horizontal row insets and the existing 28 pt scroll-content gutters / centered 840 pt column. Hover and native row selection still distinguish interactive rows. iOS keeps its original grouped list and surfaces.
